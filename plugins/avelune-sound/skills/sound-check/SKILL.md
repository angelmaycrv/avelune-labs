# Проверка звука цифрами

Ты не слышишь, поэтому оцениваешь по замерам. Скрипт: `CHECK = ${CLAUDE_SKILL_DIR}/scripts/sound_check.py` (нужны только Python и ffmpeg). Код выхода: 0 PASS, 1 WARN, 2 FAIL.

## Команды

```
python "CHECK" FILE --platform social                          # готовый ролик или трек
python "CHECK" FILE --platform social --voice V.wav --music M.wav    # стемы в том виде, как стоят в миксе
python "CHECK" FILE --sfx SFX.wav --cues CUES.json [--sfx-only]      # дорожка эффектов и список моментов
python "CHECK" --clip hit.wav --role hit                       # один звук: длина, атака, спад, пик, тембр
python "CHECK" --ab A.wav B.wav                                # чем B отличается от A (после выравнивания громкости)
python "CHECK" FILE --json report.json                         # всё то же в JSON
```
Платформы: `social` (Reels, TikTok, Shorts, VK Клипы: −14 LUFS ±1, −1 dBTP), `youtube` (−14), `music` (−14), `podcast` (−16), `tv-ebu` (−23 ±0,5), `tv-atsc` (−24, −2 dBTP), `game-mobile` (−18), `game-console` (−24), `none`.

## Что проверяется и пороги

| Проверка | PASS | Источник порога |
|---|---|---|
| Интегральная громкость | норма площадки ± допуск | ITU-R BS.1770-5, EBU R 128, ATSC A/85, справка Spotify и YouTube, AES TD1008, Sony ASWG |
| True peak | не выше потолка (обычно −1 dBTP) | те же |
| LRA | до 10 LU для соцсетей, до 8 для речи | практика сведения под телефон |
| Динамик телефона | громкость без частот ниже 150 Гц падает не больше чем на 4 LU | телефон почти не играет ниже 150–200 Гц |
| Моно | сумма теряет до 3,5 дБ (WARN до 6, дальше FAIL) | шкала Real SFX |
| Голос над музыкой (нужны `--voice`, `--music`) | медиана во время речи от 10 LU и выше (рабочий диапазон 12–20) | правило рекламного и видеосведения |
| Глубина даккинга | справочно, ориентир 6–10 дБ | там же |
| Эффекты поверх речи (`--sfx`, `--voice`) | эффект не громче голоса в тот же момент (порог −3 дБ) | разборчивость |
| Темп акцентов (`--cues`) | до 6 крупных акцентов (удар, вжух, райзер) на 15 с | правило «акценты, а не ковёр» |
| Синхрон коротких звуков (`--cues` + `--sfx`) | до 45 мс (кадр при 25 fps), WARN до 100 мс | для листа real-sfx главный `verify.py` |
| Первая секунда | пик выше −40 dBFS | звук на первом кадре входит в хук |
| Цифровая тишина (`--sfx-only`) | до 5 % окон по 250 мс тише −70 dBFS | 7 из 9 готовых SFX-роликов: 0 % |
| Тональный баланс | ориентир, только WARN: саб больше 35 %, 2–6 кГц меньше 2 %, выше 6 кГц больше 25 % | сравнивай с референсом через `--ab` |

## Как пользоваться результатом

1. Каждая строка `FAIL` и `WARN` содержит готовое исправление после `->`. Чини по одному, затем запускай проверку заново.
2. В отчёт пользователю переноси цифры, а не слова: «−14.1 LUFS / −1.2 dBTP, голос над музыкой 14 LU».
3. Сравнивай только при равной громкости: `--ab` печатает разницу в LU и команду, чтобы выровнять. Что громче, почти всегда кажется лучше.
4. Цифры не заменяют слух. В конце назови 3–5 мест, которые пользователю стоит послушать в наушниках и на телефоне: места с `WARN`, главный удар и хук.
5. Если установлен earshot, добавь `earshot critique FILE` (сравнение с профилем профессиональных роликов) и `earshot timeline FILE --cues CUES.json`.
